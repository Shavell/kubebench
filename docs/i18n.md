# Translations (i18n)

The UI ships in **English** (`en`, the reference and fallback), **Turkish**
(`tr`) and **German** (`de`). Every user-visible string goes through
[i18next](https://www.i18next.com/) with react-i18next; there are no
hard-coded UI strings. Users pick the language in Settings (default:
Automatic, from the browser).

## Namespaces and files

| Namespace | Files | Holds |
|---|---|---|
| `core` | `src/i18n/locales/<lang>.json` | the shell, common words, built-in views that are not plugins |
| `platform` | `src/core/locales/<lang>.json` | boot and password screens, status bar items, session dialogs, shared building blocks (dialogs, forms, toasts, editors, provider badges), data-layer errors |
| `updates` | `src/core/updates/locales/<lang>.json` | update check, What's new, changelog |
| `<plugin id>` | `src/plugins/<id>/locales/<lang>.json` | one plugin's strings, registered through `PluginManifest.locales` |
| `<external plugin id>` | the plugin's own `locales/` | external plugins, e.g. `examples/plugins/hello-cluster/src/locales` |

`nsSeparator` is off, so `ns:key` is never parsed from a string; components
pick the namespace with `useTranslation('<ns>')`. Display strings in a
manifest (name, description, tooltip, sidebar, command and panel titles,
resource action and settings section titles) are keys in the plugin's
namespace, resolved by `useManifestText()` / `translateManifestText()`.

## Adding strings

1. Add the key to `en.json` of the right namespace. Group nested keys by
   screen (`releases.columns.chart`).
2. Add the same key to **every** other language file of that directory
   (`tr.json`, `de.json`). Interpolation uses `{{name}}` and must use the
   same variables in every language; plurals use i18next's `_one` /
   `_other` suffixes (keep both keys in every file).
3. Use it: `const { t } = useTranslation('storage')` → `t('wizard.size')`.
   Format numbers, dates and sizes with `formatNumber`, `formatDateTime` and
   `formatBytes` from `src/i18n/format.ts`, which follow the UI language.
4. Run `npm run i18n:check`.

Tabs whose title is a UI string set `titleKey`/`titleNs` (and
`titleValues`) on the `TabDescriptor`, so open tabs follow language changes.

## Style

- Kubernetes nouns stay in English and keep their capitalisation: Pod,
  Deployment, Service, namespace, Node, Secret, ConfigMap, Helm release,
  CRD. Turkish adds suffixes with an apostrophe (`Pod'lar`,
  `Deployment'ı`, `Namespace'ler`).
- Turkish: polite "siz" form, the established glossary of
  `src/i18n/locales/tr.json` (Parola, Yapılandırma, Depolama, Erişim
  denetimi, …; "cluster" stays untranslated, as in `Cluster Gezgini`).
- German: formal "Sie", VS Code's German terminology.
- Keep strings short in tables, menus and buttons; explain in tooltips and
  dialogs.

## Adding a language

The language set is data: every file in `src/i18n/locales` is a supported
language.

1. Add `<code>.json` next to **every** `en.json` under `src/` and
   `examples/` (find them with `find src examples -name en.json -path
   '*locales*' -not -path '*/node_modules/*'`), translating every key.
2. Set `language.name` in `src/i18n/locales/<code>.json` to the language's
   own name (`"Deutsch"`); Settings lists it under that name.
3. Optionally map Monaco's message pack in
   [`src/shared/editor/monacoLocale.ts`](../src/shared/editor/monacoLocale.ts)
   (`monaco-editor/nls/lang/<code>.js`) so the editor's own menus are
   translated too.
4. Run `npm run i18n:check` and look at the UI with `?demo`.

Language detection matches the browser's tags exactly, then by base
language (`de-AT` → `de`); dates and numbers use the browser's regional
variant of the chosen language.

## The check

`npm run i18n:check` ([`scripts/check-i18n.mjs`](../scripts/check-i18n.mjs))
finds every `locales` directory under `src/` and `examples/` and fails when:

- a directory misses a language of `src/i18n/locales`, or has one that is
  not there;
- a file is not valid JSON, or a value is neither a string nor an object;
- a key of `en.json` is missing or empty in another language, or a language
  has a key that English lacks;
- a translation's `{{variables}}` differ from English.

It runs in CI, in `make test` and in the pull request checklist.
